# 代谢组下机数据定性：数据库建立与检索依据

## 核心结论

**一个分子式可以对应多个分子结构，所以分子式可以用来筛选候选，但不能作为化合物的唯一标识，更不能仅凭它确认代谢物身份。** 这不是分子式不能用，而是要把“建库时怎么区分化合物”和“定性时用什么证据匹配”分开。[1]

本文首先按常见的 **LC-MS/MS（液相色谱—串联质谱）非靶向代谢组**说明；GC-MS 的区别见文末。

> **建库按结构保存、用完整 InChIKey 关联；检索用 m/z、离子形式和分子式筛候选；定性用谱图及其他实验依据区分候选。分子式相同的不同结构，应保留，而不是删除。**

## 一、到底应该以什么为依据？

| 你要做的事情 | 应采用的依据 | 作用 |
| --- | --- | --- |
| 建立数据库、合并不同数据库中的同一化合物 | 标准化后的结构、完整 InChIKey，同时保存 SMILES／InChI | 区分和关联化合物记录 |
| 从下机数据中寻找候选代谢物 | 实测 m/z、正负离子模式、加合离子类型、同位素信息、候选分子式 | 缩小候选范围 |
| 判断具体是哪一个结构 | MS/MS 二级谱图，结合适用的保留时间、标准品等证据 | 区分候选，提高鉴定可信度 |

InChI／InChIKey 是基于结构的标识；质谱检索则需要处理离子形式，并利用谱图等实验信息。二者不是同一种用途。[2][5][7]

**特别注意：未知峰的 InChIKey 不是仪器直接测出来的。** 你通常是先得到候选结构，才能拿这个结构的 InChIKey 去其他数据库补充信息，不能靠换一个检索字段绕过结构鉴定。[1][2]

## 二、一个分子式对应多个结构，应该怎么处理？

以葡萄糖和果糖为例：

| 化合物 | 分子式 | 中性分子的单同位素精确质量 |
| --- | --- | --- |
| D-葡萄糖 | C₆H₁₂O₆ | 180.0634 Da |
| D-果糖 | C₆H₁₂O₆ | 180.0634 Da |

KEGG 中这两种化合物的分子式和精确质量相同，但分别是不同的化合物条目。**因此，分子式相同、精确质量相同，并不代表结构相同。**[3][4]

建库时，正确做法是：

> **同一个分子式下面，保留多个不同结构，而不是按分子式去重，只留一个。**

假设某个峰的候选分子式是 C₆H₁₂O₆，检索得到葡萄糖、果糖及其他候选，那么下一步应比较它们的二级谱图及其他证据。**不能因为葡萄糖排在第一位，或者更常见，就直接认定为葡萄糖。** 二级谱图提供的是进一步区分候选的信息；信息不足时，仍可能无法区分。[1][5]

## 三、数据库建议分成“化合物结构表”和“参考谱图表”

**只有“名称＋分子式”的表，更接近候选物名单，不足以承担二级质谱定性。** 可参考 MassBank 的记录方式，同时保存化合物结构、精确质量、测量条件和实际谱图。[6]

### 3.1 化合物结构表：记录“这个候选是什么”

建议至少保存以下字段：

| 字段 | 用途 |
| --- | --- |
| `compound_id` | 你自己数据库的内部编号 |
| 名称、别名 | 展示和人工查询 |
| `molecular_formula` | 分子式，用于候选筛选 |
| `exact_mass` | 单同位素精确质量，用于质量匹配 |
| `SMILES`、`InChI` | 保存结构信息 |
| 完整 `InChIKey` | 跨数据库关联、辅助结构去重 |
| 来源数据库及原始 ID | 保留来源，便于追溯 |

这些结构字段和外部数据库关联信息，在参考谱库的标准记录中都有对应设计。**高分辨质谱匹配要使用相应的精确质量，不能把普通的平均分子量当成精确质量。**[6]

**结构去重前还要统一处理规则。** 盐形式、电荷状态、互变异构和立体化学信息可能影响结构标识；不要只截取 InChIKey 的一部分，也不要把“立体化学未指定”的记录直接当成某个确定的立体异构体。建议保留原始结构和原始数据库 ID，方便核查。[2]

### 3.2 参考谱图表：记录“它在什么条件下产生什么谱图”

每条谱图关联一个 `compound_id`。建议同时保存：

| 字段 | 用途 |
| --- | --- |
| `spectrum_id` | 每条参考谱图的内部编号 |
| `compound_id` | 关联化合物结构表 |
| 前体离子 m/z | 筛选和匹配前体离子 |
| 正负离子模式 | 区分正离子和负离子谱图 |
| 加合离子类型 | 说明 `[M+H]+`、`[M+Na]+`、`[M−H]−` 等离子形式 |
| 二级碎片 m/z 和强度 | 实际的谱图匹配依据 |
| 仪器类型、碰撞能量 | 保留测量条件 |
| 保留时间、色谱条件 | 有记录时保存，用于适用条件下的辅助判断 |
| 实测／预测标记 | 区分实验谱图与计算预测谱图 |
| 来源谱库及原始谱图 ID | 追溯每条参考谱图的来源 |

以上字段设计可参考 MassBank 的记录格式。**实测谱图和计算预测谱图要明确区分，不能混成同一种证据。**[6]

这里的关系应当是：

```text
一个分子式
    ├── 候选结构 A
    │     ├── 参考谱图 A1
    │     ├── 参考谱图 A2
    │     └── 参考谱图 A3
    ├── 候选结构 B
    │     ├── 参考谱图 B1
    │     └── 参考谱图 B2
    └── 其他候选结构
```

也就是：**一个分子式可以对应多个候选结构；一个结构可以对应多条参考谱图。**[2][6]

因此，结构表合并了同一化合物的重复记录后，仍应保留它在不同离子形式、碰撞能量等条件下的谱图。**不能按 InChIKey 去重时，把谱图也删得只剩一条。**[6]

## 四、真正拿下机数据检索时，不一定要先确定分子式

### 4.1 有二级谱图：可以先直接检索参考谱库

可以先根据前体离子 m/z 和离子模式等条件筛选参考谱图，再比较二级碎片匹配情况。GNPS 的谱库搜索就是将未知物的 MS/MS 谱图与已表征化合物的参考谱图进行比较。[5]

**所以，“先知道分子式”不是所有定性流程的必需前提。**

这一步还必须注意：**仪器测到的 m/z 不等于中性分子的质量。** 同一化合物可能形成 `[M+H]+`、`[M+Na]+` 或 `[M−H]−` 等不同离子。加合离子判断错误，会影响后续分子式和结构候选的检索。[7]

### 4.2 谱库没有合适命中：再走“分子式→候选结构”的路线

可以综合精确质量、同位素分布和二级碎片，得到一个或多个候选分子式；然后在结构数据库中检索这些分子式对应的结构，再利用碎片解释或计算方法给候选排序。[8]

**即使是分子式本身，也可能存在不确定性，不能无条件认定软件排名第一的分子式一定正确。**[1][8]

建议把检索流程理解为以下两条互补路线：

```text
路线 A：实验谱库检索
未知峰及其 MS/MS 谱图
    → 根据前体 m/z、离子模式等筛选参考谱图
    → 比较二级碎片
    → 获得候选结构与匹配证据

路线 B：分子式与结构候选检索
未知峰的精确质量、同位素及碎片信息
    → 生成候选分子式
    → 检索各分子式对应的候选结构
    → 利用碎片解释或计算方法排序
    → 保留证据支持的候选范围
```

### 4.3 不必一开始就去“所有数据库”逐个检索

对建库目标，建议采用以下分工：

| 数据来源类型 | 示例 | 在流程中的主要用途 |
| --- | --- | --- |
| 实验参考谱库 | MassBank、GNPS | 提供参考 MS/MS 谱图，作为定性匹配基础 |
| 化合物结构及信息库 | PubChem、HMDB、ChEBI、KEGG | 补充候选结构、名称、数据库 ID 和关联信息 |

这是一种建库分工，而不是说这些资源的功能完全互斥。MassBank 的记录也包含结构和外部数据库关联信息。[5][6][9]

**不必一开始就把所有数据库按分子式逐个搜遍；更合理的是先整合适合检测平台的参考谱库，再扩展结构候选库。**

## 五、有些峰确实只能注释到候选范围

**数据库中能找到这个名字，不等于样品中已经确认存在这个物质。**[10]

| 现有证据 | 合理的结果表达 |
| --- | --- |
| 只有质量和分子式匹配 | 保留为候选，不直接确认具体结构 |
| 有可信的实验二级谱图匹配 | 支持更具体的推定注释，但仍需考虑无法区分的异构体 |
| 在相同分析条件下与标准品比较，保留时间及质谱特征等相符 | 支持更高可信度的确认 |

上述区分符合代谢物鉴定中按证据强度报告结果的原则。其他色谱方法下的保留时间，不能直接当作你这批数据的确认依据。[10]

如果多个异构体仍无法区分，就应保留候选集合或报告到证据支持的结构层级，**不要强行给每个峰指定一个唯一名称。增加数据库条目，不能替代缺少的实验区分信息。**[1][10]

## 六、如果数据是 GC-MS，流程需要调整

若数据是 **GC-MS**，通常应采用相应的 EI 质谱库，并结合保留指数等信息，不能直接照搬 LC-MS/MS 的谱图检索方式。NIST 也将 EI、MS/MS 和 GC 保留指数列为不同的库组件。[11]

因此，正式实施前，需要先明确：数据来自 LC-MS/MS 还是 GC-MS，以及现有文件是否包含二级谱图，还是只有 m/z、保留时间和峰面积表。

## 最后总结

**分子式是检索条件，不是唯一身份；结构标识用于关联化合物，谱图与实验信息用于判断身份。**

建库时保留“同分子式、多结构”和“同结构、多谱图”的关系；分析时保留候选与证据，不把数据库命中直接等同于确定鉴定。
