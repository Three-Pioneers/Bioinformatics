**我的建议是：采用“自动注释生成初始标签＋人工复核”的方式，而不是完全依赖自动注释，也不必每次都从零开始手动注释。**自动方法的优势是速度和一致性；人工复核的价值是结合组织背景、marker 表达和异常情况，判断软件给出的名称是否真正合理。自动注释结果应作为起点，而不是未经检查的最终结论。

下面主要讨论 **单细胞／单核 RNA 测序的细胞类型注释**。软件维护情况按 **2026 年 10 月 15 日**能核实的官方发行记录、文档和仓库信息整理；这是资料核查，不是对所有软件逐一进行安装和性能实测。

## 一、常用自动注释软件怎么比较？

首先要区分两种主要思路：**参考表达谱驱动**，即判断你的细胞像哪个已知细胞；**marker 驱动**，即把“看 marker 判断类型”转化为评分规则。后者可以不提供参考表达矩阵，但仍然依赖已有 marker 知识，不是完全不需要先验信息。

| 工具                                       | 主要原理与需要的输入                                     | 主要优势                                                     | 主要限制与适用判断                                           |
| ------------------------------------------ | -------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **SingleR**，R                             | 将待注释细胞与带标签的参考表达谱比较                     | 接入 R 流程方便；参考数据可以替换；适合作为常规注释的基线工具 | 结果受参考标签覆盖范围限制；不能把“最相似的已知类型”直接等同于真实类型。 |
| **CellTypist**，Python                     | 使用预训练或自训练的逻辑回归分类器，逐细胞预测           | 有现成模型时较省事；官方提供免疫细胞粗分和细分模型；支持自定义训练 | 必须选对模型；默认 best match 会选一个最匹配标签，并不自动保证识别出参考之外的细胞。 |
| **Seurat 标签转移／传统 Azimuth**，R、网页 | 把新数据映射到已经注释好的参考图谱，再转移标签           | 适合已有高质量、同组织参考图谱的项目；可转移分层标签，并查看参考映射结果 | 依赖参考图谱及其标签质量；参考没有的状态和类型需要额外检查。 |
| **scANVI，属于 scvi-tools**，Python        | 利用表达数据和部分已知标签，进行半监督建模与标签预测     | 可以把批次建模、数据整合和注释结合起来；适合多样本、多批次和参考迁移 | 需要训练或准备参考模型，部署较复杂；不是“用深度学习就一定更准确”。 |
| **scmap**，R                               | 将查询细胞映射到参考细胞或参考细胞群                     | 方法较直接；支持细胞级和群体级映射，并可以保留未匹配结果     | 仍然受参考覆盖范围、特征选择和相似度阈值影响；可以作为另一种参考映射方案。 |
| **ScType／scType**，R                      | 根据正向和负向 marker 对候选细胞类型打分                 | 不需要带标签的参考表达矩阵；支持自定义 marker，便于结合人工知识 | marker 的特异性和完整性非常重要；常用流程按 cluster 汇总，混合细胞群可能被概括成一个标签。 |
| **scCATCH**，R                             | 识别 cluster marker，再与组织相关的 CellMatch 数据库匹配 | 接近传统“找 marker—查类型”的思路，便于解释                   | 依赖前面的聚类、差异基因和数据库覆盖；重点是 cluster 注释，而不是对每个细胞独立判断。 |
| **SCSA**，Python                           | 根据差异基因及数据库中的 marker 证据进行评分             | 可接收 Seurat、Scanpy 等产生的 marker 结果；支持自定义 marker 数据库 | 输入差异基因的质量、筛选阈值和数据库版本都会影响结果；更适合辅助给 cluster 命名。 |



**特别注意：Seurat 的 FindClusters() 是聚类，不是自动命名细胞类型。**这里说的 Seurat 自动注释，主要是 FindTransferAnchors()、TransferData()、MapQuery() 等参考标签转移功能。

也不建议简单给这些软件排一个“准确率第一、第二”。例如，2024 年一项使用实验标记免疫细胞亚群的研究，分别评估了数据集内预测、跨数据集预测、亚型区分和未知类型识别；结果显示，任务难度、训练数据和测序技术都会影响表现，未知类型识别尤其困难。**某篇论文中的排名，不等于在你的组织和参考库上仍然成立。**

这里必须把“有新版本”“仍在发行平台上”“数据库更新”“网页还能打开”分开，不能用其中一项代替全部。

### SingleR 最容易被误判

网上有人说“SingleR 不维护了”，往往是看到了 **dviraran/SingleR 旧仓库**。该仓库明确说明旧版本停止维护，并引导用户转向 Bioconductor；这不代表现在的 SingleR 包停止维护。

### 软件更新，不代表你使用的参考库也更新了

例如，把 CellTypist 软件升级，并不意味着你之前下载的模型文件自动变成新模型；SCSA 的代码版本和它使用的 marker 数据库也不是同一个概念。官方文档分别提供模型选择或数据库选择机制。

因此，我建议长期项目至少分别记录：

**软件版本＋参考图谱／模型版本＋marker 数据库版本＋主要参数。**

这比只记录“用 SingleR 注释”或“用 CellTypist 注释”更有意义。

## 三、自动注释相比手动注释，有哪些优劣？

这里的“手动注释”并不是人工逐个查看所有细胞，而通常是结合聚类、差异基因、marker 表达、组织背景和文献进行判断；它同样依赖前面的计算分析。

| 比较维度             | 自动注释                                            | 手动注释                                                     |
| -------------------- | --------------------------------------------------- | ------------------------------------------------------------ |
| **效率**             | 适合批量处理多个样本，减少反复查 marker 的工作      | 复杂组织和大量亚群需要较多人工检查                           |
| **一致性与复现**     | 固定模型、参考、参数和环境后，更容易保持统一标准    | 分析人员、使用的文献和命名习惯不同，可能产生差异             |
| **常见已知细胞类型** | 有匹配参考时，可以高效给出稳定的初始判断            | 能判断，但未必比成熟自动方法更准确                           |
| **参考之外的细胞**   | 可能被归到最接近的已知类型，或成为未分配结果        | 可以结合背景提出其他解释，但也不能仅凭主观判断确认新类型     |
| **细亚型与特殊状态** | 受到参考标签分辨率限制；可能遗漏或过度细分          | 可灵活结合研究问题，但更依赖专业知识，也容易过度解释         |
| **可解释性**         | marker 打分方法通常较直观；复杂分类模型需要额外诊断 | 可以形成清楚的 marker 和文献证据链，前提是把判断过程记录下来 |



这些取舍在自动评分工具的原始研究、实验标签基准评估以及官方注释诊断流程中都有体现；不能简单归结为“自动不准、人工一定准”。

**手动注释也不是天然的金标准。**当研究把人工标签作为评价标准时，“自动结果与人工一致”首先表示两套标签的一致性，并不自动等于独立实验验证的正确率。采用这种评价方式的 LLM 注释研究，也需要按这一点理解其结果。

## 四、实际分析中，最需要防范的几个问题

### 1. 软件能够给出标签，不代表这个标签可信

以 CellTypist 为例，默认 best match 模式会为每个细胞选择得分最高的类型；prob match 模式才允许得到零个、一个或多个匹配标签。因此，**“所有细胞都成功注释”不能当作质量指标。**

SingleR 则提供 pruned.labels，把部分低置信度结果标记为 NA。但其官方文档也说明，默认筛选依赖一定假设，不能保证排除所有系统性误注释。

### 2. 多个软件一致，也可能一起出错

这是一个需要注意的逻辑问题：**如果两个软件依赖同一个不合适的参考，结果一致并不构成两份独立证据。**

而 marker 数据库本身也可能不一致。2025 年的 Cell Marker Accordion 研究展示了：对同一数据使用不同 marker 来源，可能产生不同的细胞类型注释。因此，更换数据库有时和更换算法一样值得检查。

### 3. 一个 cluster，不一定只有一种细胞类型

实验标签基准研究显示，部分免疫亚型在表达空间中高度相近，聚类结果不能完全对应真实亚型。因此，不能为了让 UMAP 图“整齐”，就强行给每个 cluster 只保留一种细胞名称。

同样，CellTypist 的多数投票会按子群统一标签。按这一机制推断，当一个子群包含少数不同细胞时，其原始预测可能被多数标签覆盖，所以建议保留投票前后的结果用于检查。

### 4. “细胞类型”和“细胞状态”要分开记录

增殖、应激、炎症应答等表达程序，不应不加区分地替代细胞谱系名称。例如，分析中可以分别记录“属于哪类细胞”和“处于何种状态”，而不是因为出现一个特殊表达簇，就直接命名为新细胞类型。参考之外的状态和新类型也是参考映射方法需要谨慎处理的问题。

### 5. 不同软件的分数不能直接横向比较

SingleR 的评分是基于相关性的分数，**0.9 不能解释为“90% 正确”**。不同工具的概率、相似度、置信度和分数差值，需要按照各自定义解释，也不能统一套一个阈值。

## 五、现在实际选工具，我会怎么选？

以下是根据上述机制、维护证据和部署成本给出的选型建议，不是统一准确率排名。

**对于常规人类数据、R／Seurat 分析流程：**我会先用 **SingleR 或 Seurat 参考标签转移**，再检查 marker。已有高质量同组织参考图谱时，更值得优先测试标签转移；需要一个容易接入现有 R 流程的基线时，可以先测试 SingleR。

**对于免疫细胞注释：**我会把 **CellTypist**列为重点候选，但先确认模型的细胞类型范围，并分别看粗粒度和细粒度结果，而不是对任何组织直接套默认免疫模型。

**对于多批次整合、已有参考数据且需要批量迁移标签的项目：**可以重点评估 **scANVI**。它的价值在于将标签信息与统计建模结合，不只是换一个“更高级”的分类器。

**对于缺少合适参考表达谱，但有较可靠 marker 知识的项目：**可以用 **ScType、SCSA 或 scCATCH**辅助判断。我更倾向于把它们作为 marker 证据整理和候选类型排序工具，再结合组织背景确定最终标签。

### 推荐的交付流程

我建议采用：

**数据质控与异常检查 → 自动生成初始标签 → 检查各类 marker → 复核低置信度和冲突结果 → 确定最终标签并保留证据。**

在这一流程中，人工复核不应只是“看一眼 UMAP”，而应查看标签与 marker 是否一致、不同样本是否有异常分布，以及不确定细胞是否需要保留为未分配或更上一级类别。官方 SingleR 诊断文档和参考映射教程都提供了相应检查思路。

最终结果中，我建议保留**原始自动标签、最终标签、置信度、参考版本和人工修改理由**，不要直接覆盖掉原始结果。这样后续更换参考库或发现异常时，才能追溯。

## 六、较新的方案是否值得关注？

**Pan-human Azimuth 值得在人类数据上评估。**它与传统 Azimuth 的参考映射流程需要区分：官方将它描述为跨组织的人类单细胞／单核 RNA 测序神经网络分类器，并提供 Python 包和 R 接口。2026 年的 v1 更新加入了 Unassigned 标签，并对置信度进行了校准；不过官网目前仍以预印本介绍完整方法，不能只因更新就认定优于所有成熟工具。

**10x Genomics 也提供官方自动细胞注释。**它已经可以接入相关 Cell Ranger 流程，适合希望减少额外部署工作的用户；但官方同样提醒，参考中缺少的样本类型、肿瘤等异常表达背景，需要仔细复核。

**LLM 辅助注释，例如 CASSIA 一类方法，可以作为候选标签和解释的补充来源。**已有原始研究显示其潜力，也明确讨论了过度自信、幻觉和结果解释问题；我不建议把一段 marker 列表交给模型后，就直接把回复作为最终注释。

------

**综合来看，长期主流程可以优先考虑 SingleR、CellTypist、Seurat 标签转移和 scANVI；ScType、SCSA、scCATCH 可作为 marker 驱动的辅助方案。维护状态要看，但参考是否适合你的物种、组织和细胞分辨率，同样重要。最终应比较的是“工具＋参考库＋复核流程”，而不是只比较软件名称。**
